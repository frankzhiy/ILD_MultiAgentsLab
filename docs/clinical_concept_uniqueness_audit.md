# 临床概念唯一性核查

日期：2026-11-03。范围：四科正式意见、会中回答、主持人候选与综合、前端展示；实例为运行 `20261103_202834_76-IPF`。

以下为修复前核查记录。后续修正的权威定义与兼容策略见 [临床概念契约](clinical_concepts.md)；未改写已保存病例结果。唯一性指同一概念使用一致定义、身份和当前状态，不要求不同专科给出相同意见。

## 1. 把握度被转换成判断状态（优先修正）

位置：`src/agents/common/decision_state.py:557`。

`record_discussion_answers` 将会中回答的 high/moderate/low 把握度分别转换为 supported/favored/possible。回答是否有把握与它对某疾病的支持程度并不等价。负向判断也可以有较高把握，资料边界也可以被明确说明。首轮字段由模型独立给出，会中记录却采用这一自动换算，同一 status 的产生规则不一致。

76 号风湿科会中回答包含“当前不支持具体CTD相关ILD”等内容，会中存储状态为 favored。该派生记录没有保留独立的 confidence、direction 字段。不能据此声称模型把疾病判为阳性，但下游无法仅靠该状态确定支持的对象。

建议：回答完成情况、回答把握度与诊断判断保持各自含义；停止从 confidence 推导诊断状态。会中回答作为回答保存，不伪装成完整的专科诊断判断。

## 2. 支持方向缺少唯一、明确的对象（优先修正）

位置：`src/agents/common/initial_output.py:139`、`front/src/pages/workspaces/SpecialtyWorkspace.jsx:90`。

76 号风湿科 `rhu_01` 的实际组合：

- statement：当前不支持具体结缔组织病或ANCA相关血管炎。
- status：supported。
- direction：against。
- confidence：moderate。

如果 supported 指“该否定陈述有依据”，against 指“反对疾病成立”，它们可以逻辑相容；问题是两者对象不同却没有明确表示。页面同时展示“支持”和“方向：反对”，医生及下游 Agent 都需自行猜测。

status 同时包含 supported/favored/possible、not_assessable/not_applicable、unclassifiable，混入支持程度、可评价性、适用性与分类结果；另有 assessability 和 confidence 再次表达部分含义。

建议：明确判断对象；每个维度只回答一个问题。收敛现有重叠字段，不再叠加一套同义状态。缺少支持、存在反证与已排除不得互换。

## 3. 同一诊断存在多个独立表示，缺少贯穿的身份（优先修正）

位置：`src/agents/common/diagnostic_resolution.py:11`、`src/agents/common/team_synthesis.py:70`。

探索候选和审定去向使用 candidate_id；当前临床问题下的候选没有 candidate_id，只有诊断名称。标题 primary_diagnosis、整体意见 diagnosis 与主要问题 statement 又分别生成。

76 号 IPF 分别写为“特发性肺纤维化（IPF）”和“特发性肺纤维化”；感染后肺病的名称还带有不同的结核归因限定。名称、病因层级与关系需要显式关联，不能通过模糊字符串匹配认定相同。

讨论后新增 NSIP 只出现在当前问题候选，未进入已有探索候选及其审定编号体系。这可以是正常的新候选，但当前没有统一的身份与阶段记录来解释这种变化。

建议：同一病例中同一候选使用稳定编号；名称及别名、专科来源判断、当前团队取舍分别关联它。新候选先登记；疾病与形态、病因或综合征的关系单独表达。不同时间或不同判断范围不能强制合并。

## 4. 不采纳候选被归入“排除记录”（展示语义错误）

位置：`front/src/components/Consultation.jsx:32` 至 `:51`。

rejected 候选被分入标题为“模式、大类、发现及排除记录”的分组。rejected 表示本次不采纳，原因可以是证据弱、解释力较低或归类不合适；不能统一理解为疾病已被排除。76 号 HP 的审定理由为患者特异支持不足、当前不进入主要排序，并不等于排除。

建议：以“本次未保留的候选及原因”表达候选去向；若确有排除结论，独立记录明确依据，不能从 rejected 自动推导。

## 5. 同一字段在不同页面有多套术语映射（应随契约一起统一）

位置：`front/src/components/JudgmentDimensions.jsx`、`TeamSynthesis.jsx`、`ClinicalReport.jsx`、`Consultation.jsx`、`front/src/pages/workspaces/SpecialtyWorkspace.jsx`。

例如 alternative 在讨论页显示“竞争解释”，新报告显示“保留候选”；unknown 把握度有“尚不能评定把握度”和“把握度未定”；specific_diagnosis 有“形成具体诊断”和“具体诊断意见”。本次新增的报告页也重复定义了这些映射。

这不必然改变医学结论，但相同字段的临床含义不应由页面自行决定。先固定含义，再由共享映射提供一致标签；确实不同的维度不能仅因名称相近而合并。

## 内存反例验证

以 76 号最终综合的副本调用 `TeamSynthesis.model_validate`，以下三种变化均未被该模型校验拒绝：

1. 同一主要问题中，添加同名候选，一条 preferred，另一条 alternative。
2. 将探索中 IPF 的审定改为 rejected，当前问题仍保留 IPF 为 preferred。
3. 将主要诊断标题改为另一个疾病，当前问题与整体意见仍为 IPF。

此验证仅证明数据模型缺少这些一致性检查，不代表修改后的历史文件可绕过最终报告的快照校验。实验只修改内存副本，未写入病例文件，也未调用模型。未进行全流程对照，因此不能量化这些问题对 CPFE 漏诊的贡献。

## 建议固定的概念边界

| 概念 | 唯一负责回答的问题 | 不能替代它的概念 |
| --- | --- | --- |
| 患者事实状态 | 原文是阳性、阴性、未知还是历史记录 | 模型对疾病的推断 |
| 可评价性 | 当前材料是否允许评价该对象 | 疾病是否存在 |
| 判断方向 | 对明确对象支持、反对还是未定 | 判断把握度 |
| 判断把握度 | 对该项判断有多大把握 | 支持程度或确诊状态 |
| 候选地位 | 本次首选、保留或未保留及原因 | 已确诊或已排除 |
| 证据满足状态 | 某项所需信息是否充分提供 | 讨论是否结束、疾病是否确诊 |
| 团队接受程度 | 各科是否接受当前综合意见 | 诊断正确性或确定程度 |

最小修正顺序：先确定共享定义和候选身份，再修正会中转换与一致性检查，最后统一所有页面标签。保留现有版本历史及专科分歧，不将历史判断改成新结论，不以措辞正则或诊断名称黑名单替代语义契约。
