# 临床概念契约

同一概念使用一致定义和身份；不同问题分别表达。专科分歧和历史变化允许存在，不用“统一概念”强行统一医学意见。

## 判断分别回答什么

| 概念 | 表达 | 含义与边界 |
| --- | --- | --- |
| 患者事实状态 | 阳性、阴性、未知、历史等原文信息 | 属于患者事实层，不由模型推断或指南补出 |
| 判断对象 | 专科 `conditions.subject`；诊断维度 `subject` | 使用中性对象，如“CTD相关ILD”；避免对“不支持某病”再标一个反对方向 |
| 可评价性 | 可评价、部分可评价、不可评价 | 当前材料是否允许评价该对象；不可评价不是阴性 |
| 判断方向 | 有正向支持、尚缺支持依据、存在反对依据、已有依据排除、判断方向未定 | 支持不足与反证不同；反证与排除不同；正向支持也不等于确诊 |
| 判断把握度 | 高、中、低、未知 | 对本项判断的把握度；高把握度可以属于负向判断，不能自动变成支持疾病 |
| 证据方向 | 支持、削弱、中性 | 相对原子陈述 `claim.statement`，与相对疾病对象的判断方向分开；证据支持否定陈述不表示疾病阳性 |
| 会诊关注级别 | 会诊重点、重要备选关注等 | 专科内部优先关注什么，不决定全病例主诊断 |
| 临床关系 | 主要解释、竞争解释、急性叠加、并存问题等 | 解释什么问题、与主要病变是什么关系，不是确定程度 |
| 候选地位 | 当前首选、保留候选、尚未择定 | 当前问题内的相对排序；首选不自动等于确诊 |
| 候选去向 | 首选、保留、待讨论、本次未保留 | 未保留另列原因：支持不足、解释力较弱、存在反证、已有依据排除、范围不符 |
| 诊断意见类型 | 具体诊断意见、暂定诊断意见、有限鉴别、推理待讨论 | 当前主要判断的具体程度和推理完成情况，不用运行完成证明确诊 |
| 判断边界 | 已能判断、尚不能判断、原因、影响 | 某确证条件尚未满足，不会自动撤销有正向线索的候选；缺少哪些条件在证据需求中说明 |
| 证据满足状态 | 已满足、部分满足、尚缺资料 | 仅针对该项信息需求；本轮不再追索不等于已满足 |
| 会中回答 | 回答完成情况、回答把握度 | 问题是否得到回答与疾病是否被肯定分开；正式诊断变化另经判断更新保存 |
| 团队接受程度 | 共同接受、带边界接受、主持人综合、明确分歧 | 各科对本版综合的态度，不证明诊断正确、确诊或资料齐备 |

“尚不能确立”说明确证边界；“仍值得怀疑”说明有正向线索、仍值得保留比较。两者可以同时成立，分别记录候选依据、地位和未满足的条件。不能仅凭“尚未排除”列入候选。

## 同一候选只维护一份身份

- `diagnostic_exploration.candidates` 登记病例内稳定 `candidate_id`、唯一标准名称、层级与明确别名。新候选先登记，再参与当前判断。
- `problems[].candidates` 引用该编号；模型不独立输出候选名称。`diagnostic_resolution.primary_candidate_id` 指向主要问题首选，名称与主标题由登记解析。无具体候选时使用主要问题陈述。
- 每个问题内同一编号只出现一次，最多一个首选。当前地位、审定去向和主诊断引用必须一致；未保留候选仍留在登记及审定记录中。
- 后续轮次保留旧编号、标准名称、层级及已登记别名；不能删除身份或把旧编号用于另一概念。新解释使用新编号。
- 只对空白、大小写及括号做排版归一。医学同义关系必须明确声明；疾病、形态模式、病因限定和组合综合征不自动合并。综合意见是围绕这些身份的临床论述，不是第二份自由命名的主诊断标题。

## 兼容与校验

共享类型及字段说明位于 `src/agents/common/clinical_concepts.py`；页面用 `front/src/components/clinicalConcepts.js` 的共同术语。四科正式意见、会中判断更新和诊断维度不再向模型索取混合 `status`。

程序校验重复身份、登记覆盖、首选与去向冲突、跨轮身份变化和引用有效性。声明排除须提供实际患者证据；程序能核对引用存在，医学上是否充分仍须专业判断，不能靠格式校验保证。

旧 `status` 按原样保留用于历史阅读和快照核验；不换算成新方向或新把握度。旧版 `against` 未区分支持不足与反证，页面和模型输入会提示歧义。旧会中回答不从 `supported/favored/possible` 推算回答把握度。旧候选缺少贯穿编号时保留原始名称，不猜测别名、不重新诊断、不重写结果。

新增规则通过合成病例反例测试；历史76号病例用于读取、快照和展示兼容检查。该检查不等于重新验证其临床诊断，也不强制产生CPFE。
